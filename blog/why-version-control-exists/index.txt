21:T18ba,<p>Imagine a world without Git. Two developers share one codebase, and the only copy of the &quot;working&quot; code lives on a ~1GB pendrive.</p>
<p>There is no cloud repository. There is only <code>The Pendrive</code>. If you want to change the code, you need The Pendrive. If you have The Pendrive, you hold the power. If you don&#39;t? You wait.</p>
<p>This was a reality for many teams in the 90s, and every problem it caused is something version control was built to fix.</p>
<blockquote>
<p>With one shared copy of the code, whoever saves last wins.</p>
</blockquote>
<p>Let&#39;s walk through one Tuesday of the &quot;Pendrive Workflow&quot;, and then see what version control changes.</p>
<hr>
<h2 id="only-one-person-can-work-at-a-time">Only One Person Can Work at a Time<a class="heading-anchor" href="#only-one-person-can-work-at-a-time" aria-label="Link to this section">#</a></h2>
<p>Here is a standard Tuesday for a team of two developers, <code>Krishna</code> and <code>Ram</code>, without version control.</p>
<p><code>09:00 AM:</code> Krishna grabs The Pendrive. He copies the code to his laptop to fix a critical login bug.</p>
<p><code>09:30 AM:</code> Ram needs to work on the payment gateway. He asks Krishna for the drive.</p>
<p><code>The Bottleneck:</code> Krishna shouts, <em>&quot;I&#39;m not done! If you take it now, the code is broken!&quot;</em> Ram has to sit there and spin around in his chair, because he literally cannot code until Krishna is finished.</p>
<p>Development isn&#39;t parallel; it&#39;s <code>serial</code>. It&#39;s a traffic jam where only one car can move at a time.</p>
<p><img src="/posts/2026-01-10-why-version-control/assets/waiting-for-code-turns.png" alt="Waiting for Pendrive" loading="lazy" /></p>
<h3 id="the-finalfinalv2-tragedy">The &quot;Final_Final_v2&quot; Tragedy<a class="heading-anchor" href="#the-finalfinalv2-tragedy" aria-label="Link to this section">#</a></h3>
<p>Krishna is taking his sweet time, so Ram gets frustrated. He decides to work on an old copy of the code he saved on his desktop last week, and writes brilliant code for three hours.</p>
<p>Finally, he gets The Pendrive. He opens the folder to save his work and sees this:</p>
<blockquote>
<p><code>Project_Source_Code</code> -&gt; <code>Project_Source_Code_Final</code> -&gt; <code>Project_Source_Code_Final_FINAL</code> -&gt; <code>Project_Source_Code_Final_v2_DO_NOT_DELETE</code></p>
</blockquote>
<p>Which one is the real one? Who knows!</p>
<p>Ram guesses. He copies his files onto the drive. <code>Disaster strikes.</code></p>
<p>Because Ram was working on an old version, he just overwrote the bug fix Krishna spent all morning writing. Krishna&#39;s code is gone. There is no <code>Ctrl+Z</code> for a file replacement on a USB stick.</p>
<h2 id="the-last-person-to-save-wins">The Last Person to Save Wins<a class="heading-anchor" href="#the-last-person-to-save-wins" aria-label="Link to this section">#</a></h2>
<p>In Git, if you and I change the same line of code, Git stops us with a merge conflict and makes us decide which code wins.</p>
<p>With the pendrive? <code>The last person to save wins.</code><br>If I fix a bug, and you upload a file you worked on yesterday that <em>doesn&#39;t</em> have the fix, my bug comes back from the dead. This leads to the infamous &quot;I swear I fixed this yesterday!&quot; conversation.</p>
<h2 id="there-is-no-undo">There Is No Undo<a class="heading-anchor" href="#there-is-no-undo" aria-label="Link to this section">#</a></h2>
<p><img src="/posts/2026-01-10-why-version-control/assets/lost-versions.png" alt="Lost Versions" loading="lazy" /></p>
<p>Beyond overwriting work, relying on a physical device adds physical risks:</p>
<ul>
<li><strong>No History:</strong> If the code breaks today, you can&#39;t go back to how it looked yesterday.</li>
<li><strong>Corruption:</strong> If the pendrive is lost, corrupted, or washed in a pair of jeans, the entire project is gone.</li>
</ul>
<p>Eventually, the software world realized this was unsustainable. Teams needed a way to work at the same time, keep a history of every change, and never lose work to whoever saved last. That need gave birth to <code>Version Control Systems (VCS)</code>.</p>
<hr>
<h2 id="version-control-is-a-time-machine-for-code">Version Control Is a Time Machine for Code<a class="heading-anchor" href="#version-control-is-a-time-machine-for-code" aria-label="Link to this section">#</a></h2>
<p>A <code>Version Control System (VCS)</code> is software that records every change to a project, so developers can store versions, compare them, and go back when something breaks.</p>
<p>Think of it as a <code>Time Machine</code> for your code. Every change to every file is tracked, so you can return to any earlier version, and several people can work on the same project without overwriting each other. (1)</p>
<h3 id="what-changes-for-krishna-and-ram">What Changes for Krishna and Ram<a class="heading-anchor" href="#what-changes-for-krishna-and-ram" aria-label="Link to this section">#</a></h3>
<ul>
<li><strong>History Tracking:</strong> Every change is recorded. You can see exactly who changed which line, and when. (No more blaming the wrong person!)</li>
<li><strong>Branching and Merging:</strong> Developers create &quot;branches&quot; (parallel universes) to work independently. Ram works on payments while Krishna works on login, and they merge later without overwriting each other.</li>
<li><strong>Traceability:</strong> Changes can be linked to specific issues or features, so you can see why the code evolved the way it did.</li>
<li><strong>Safety:</strong> Every change can be reviewed before it&#39;s merged, which means fewer broken builds.</li>
</ul>
<p><img src="/posts/2026-01-10-why-version-control/assets/full-worflow.png" alt="Pendrive Problem" loading="lazy" /></p>
<hr>
<p>The pendrive had one copy of the truth, and whoever saved last owned it. Version control gives everyone their own copy, a full history, and a way to merge, so nobody&#39;s Tuesday morning of work disappears again.</p>
