21:T6360,<p>Most AWS Glue and Lambda code gets tested the same way: deploy it, run the job, and read the CloudWatch logs. Every fix means another deploy and another wait, and the only bugs you catch are the ones that happened to show up in that run.</p>
<p>The logic inside those jobs (cleaning a name, parsing a record, deciding where a file goes) doesn&#39;t need AWS to be tested. It&#39;s plain Python.</p>
<blockquote>
<p>Test the logic before it reaches AWS, and let the pipeline refuse to ship anything that fails.</p>
</blockquote>
<p>As a data engineer, I&#39;ve set up Jenkins pipelines that do exactly this. This post walks through one end to end: <code>uv</code> and <code>pyproject.toml</code> for dependencies, <code>ruff</code> for formatting and linting, <code>pytest</code> and <code>moto</code> for tests, <code>JFrog Artifactory</code> for build artifacts, and <code>Terraform</code> to deploy the tested code to S3 for Glue or Lambda to run.</p>
<aside class="callout callout-tldr">
      <p class="callout-title">TL;DR</p>
      <div class="callout-body"><p><strong>Problem:</strong> Glue and Lambda code is often only tested by deploying it, so bugs are found late and slowly.</p>
<p><strong>Fix:</strong> keep business logic in plain Python modules, test it with <code>pytest</code> (and AWS calls with <code>moto</code>) on every pull request, and only let CD deploy the exact artifact that passed.</p>
</div>
    </aside>

<h2 id="the-pipeline-ci-checks-the-code-cd-ships-it">The Pipeline: CI Checks the Code, CD Ships It<a class="heading-anchor" href="#the-pipeline-ci-checks-the-code-cd-ships-it" aria-label="Link to this section">#</a></h2>
<h3 id="continuous-integration-ci">Continuous Integration (CI)<a class="heading-anchor" href="#continuous-integration-ci" aria-label="Link to this section">#</a></h3>
<p>Triggered on each commit or pull request, CI runs:</p>
<ol>
<li><strong>Set Up the Environment</strong>: install <code>uv</code> and sync dependencies from <code>pyproject.toml</code>.</li>
<li><strong>Code Quality Checks</strong>:<ol>
<li><strong>Formatting</strong>: <code>uv run ruff format --check</code> fails if any file isn&#39;t formatted.</li>
<li><strong>Linting</strong>: <code>uv run ruff check .</code> catches syntax issues, unused imports and common errors.</li>
<li><strong>Import Sorting</strong>: <code>uv run ruff check --select I</code> enforces import order.</li>
</ol>
</li>
<li><strong>Unit Testing</strong>: <code>uv run pytest</code>, producing JUnit reports.</li>
<li><strong>Artifact Packaging</strong>: zip the tested code and upload it to JFrog Artifactory.</li>
</ol>
<aside class="callout callout-tip">
      <p class="callout-title">Tip</p>
      <div class="callout-body"><p>Run the formatter before the linter. A lot of lint errors are formatting issues, and the formatter fixes those for free. You will thank me later ;)</p>
</div>
    </aside>

<h3 id="continuous-deployment-cd">Continuous Deployment (CD)<a class="heading-anchor" href="#continuous-deployment-cd" aria-label="Link to this section">#</a></h3>
<p>Once CI passes, CD deploys:</p>
<ol>
<li><strong>Artifact Download</strong>: fetch the build that CI just tested from Artifactory.</li>
<li><strong>Terraform Plan</strong>: preview the infrastructure changes.</li>
<li><strong>Terraform Apply</strong>: apply them.</li>
<li><strong>Trigger Execution</strong>: Glue or Lambda jobs pick up the new code from <code>S3</code>.</li>
</ol>
<p><img src="/posts/2025-03-21-ci-cd-pipeline/assets/ci_cd.png" alt="CI/CD Pipeline" loading="lazy" /></p>
<p>The important part is that CD never rebuilds anything. It deploys the exact zip that passed the tests.</p>
<hr>

<h2 id="toolchain-summary">Toolchain Summary<a class="heading-anchor" href="#toolchain-summary" aria-label="Link to this section">#</a></h2>
<ol>
<li><a href="https://www.jenkins.io/">Jenkins</a> – CI/CD orchestrator</li>
<li><a href="https://docs.pytest.org/en/stable/">pytest</a> – Testing framework for business logic</li>
<li><a href="https://docs.getmoto.org/en/latest/docs/getting_started.html">moto</a> – Mocks AWS services for offline tests</li>
<li><a href="https://docs.astral.sh/ruff/">ruff</a> – Python linter, formatter and import sorter in one</li>
<li><a href="https://docs.astral.sh/uv/">uv</a> – Fast Python dependency manager</li>
<li><a href="https://www.terraform.io/">Terraform</a> – Infrastructure as Code for AWS resources</li>
<li><a href="https://jfrog.com/">JFrog Artifactory</a> – Artifact repository for build outputs</li>
</ol>
<hr>
<p>The tools matter less than the order they run in. A bug in <code>clean_name</code> should fail a pull request in seconds, not a Glue job run after deployment.</p>
