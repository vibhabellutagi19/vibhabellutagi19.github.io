Was it a 401? A 500? Did the server even get the request? The browser hides most of that.</p>
<p>With one terminal command you can send the same request yourself and see every line the server sent back.</p>
<blockquote>
<p>cURL is a browser without the window: it sends a request and shows you exactly what came back.</p>
</blockquote>
<p>cURL (short for &quot;Client URL&quot;) is a command-line tool for transferring data using URLs. It&#39;s free, open source, and comes pre-installed on Linux, macOS and Windows 10+. This post covers why it&#39;s worth learning, your first requests, how to read a full request and response, and the difference between GET and POST.</p>
<h2 id="why-not-just-use-the-browser">Why Not Just Use the Browser?<a class="heading-anchor" href="#why-not-just-use-the-browser" aria-label="Link to this section">#</a></h2>
<p>A <strong>server</strong> is a computer that stores and provides information to other computers over a network, which are called <strong>clients</strong>. When you open a website, your browser (the client) sends a request to a web server, and the server responds with the page.</p>
<p>The browser is built to <em>show</em> you the result, not the conversation. But as a developer, you often want to:</p>
<ul>
<li>Test an API during development</li>
<li>Automate file downloads</li>
<li>Debug what a server actually responded with</li>
<li>Write scripts that talk to web services</li>
</ul>
<p>For all of these, you want to send a precise request and see the raw response. That&#39;s what cURL does.</p>
<h3 id="curl-your-command-line-messenger">cURL: Your Command-Line Messenger<a class="heading-anchor" href="#curl-your-command-line-messenger" aria-label="Link to this section">#</a></h3>
<p>Think of cURL as a messenger that works directly from your terminal. Instead of clicking buttons in a browser, you type a command that:</p>
<ol>
<li><strong>Sends a request</strong> to a server (asking for data or sending information)</li>
<li><strong>Receives the response</strong> (the data you asked for, plus details about it)</li>
<li><strong>Displays the result</strong> right in your terminal (or saves it to a file)</li>
</ol>
<h2 id="your-first-request">Your First Request<a class="heading-anchor" href="#your-first-request" aria-label="Link to this section">#</a></h2>
<div class="code-block">
      <div class="code-head">
        <span class="code-lang"></span>
        <button type="button" class="code-copy">Copy</button>
      </div>
      <pre class="shiki"><code>curl https://api.github.com</code></pre>
    </div><p>This fetches data from GitHub&#39;s API and prints it in your terminal. No browser, no clicking.</p>
<h2 id="the-flags-youll-use-most">The Flags You&#39;ll Use Most<a class="heading-anchor" href="#the-flags-youll-use-most" aria-label="Link to this section">#</a></h2>
<p><strong>Save output to a file:</strong></p>
<div class="code-block">
      <div class="code-head">
        <span class="code-lang"></span>
        <button type="button" class="code-copy">Copy</button>
      </div>
      <pre class="shiki"><code>curl https://api.github.com -o output.json</code></pre>
    </div><p><strong>Send a request header:</strong></p>
<div class="code-block">
      <div class="code-head">
        <span class="code-lang"></span>
        <button type="button" class="code-copy">Copy</button>
      </div>
      <pre class="shiki"><code>curl -H &quot;Accept: application/json&quot; https://api.github.com</code></pre>
    </div><p><strong>Make a POST request with data:</strong></p>
<div class="code-block">
      <div class="code-head">
        <span class="code-lang"></span>
        <button type="button" class="code-copy">Copy</button>
      </div>
      <pre class="shiki"><code>curl -X POST https://httpbin.org/post \
  -H &quot;Content-Type: application/json&quot; \
  -d '{&quot;name&quot;: &quot;John&quot;, &quot;age&quot;: 30}'</code></pre>
    </div><p><strong>See the response headers (and status code):</strong></p>
<div class="code-block">
      <div class="code-head">
        <span class="code-lang"></span>
        <button type="button" class="code-copy">Copy</button>
      </div>
      <pre class="shiki"><code>curl -i https://api.github.com</code></pre>
    </div><h2 id="-v-shows-the-whole-conversation">-v Shows the Whole Conversation<a class="heading-anchor" href="#-v-shows-the-whole-conversation" aria-label="Link to this section">#</a></h2>
<p>Every time you use curl, you send an HTTP <strong>request</strong>. A request has:</p>
<ol>
<li>Method (GET, POST, PUT, DELETE, etc.)</li>
<li>URL (where you&#39;re sending the request)</li>
<li>Headers (metadata about your request)</li>
<li>Body (optional data you&#39;re sending)</li>
</ol>
<p>The server sends back an HTTP <strong>response</strong> with:</p>
<ol>
<li>Status code (200 = success, 404 = not found, 500 = server error, etc.)</li>
<li>Headers (metadata about the response)</li>
<li>Body (the actual data/content)</li>
</ol>
<p>The <code>-v</code> (verbose) flag shows <strong>both</strong>:</p>
<div class="code-block">
      <div class="code-head">
        <span class="code-lang"></span>
        <button type="button" class="code-copy">Copy</button>
      </div>
      <pre class="shiki"><code>curl -v https://httpbin.org/get</code></pre>
    </div><p>Here&#39;s how to read what comes back:</p>
<div class="code-block">
      <div class="code-head">
        <span class="code-lang"></span>
        <button type="button" class="code-copy">Copy</button>
      </div>
      <pre class="shiki"><code>&gt; GET /get HTTP/1.1              ← REQUEST METHOD
&gt; Host: httpbin.org               ← REQUEST HEADER
&gt; User-Agent: curl/7.x            ← REQUEST HEADER
&gt; Accept: */*                     ← REQUEST HEADER

&lt; HTTP/1.1 200 OK                 ← RESPONSE STATUS
&lt; Content-Type: application/json  ← RESPONSE HEADER
&lt; Content-Length: 315             ← RESPONSE HEADER

{                                 ← RESPONSE BODY
  &quot;args&quot;: {},
  &quot;headers&quot;: {...},
  &quot;url&quot;: &quot;https://httpbin.org/get&quot;
}</code></pre>
    </div><aside class="callout callout-tip">
      <p class="callout-title">Tip</p>
      <div class="callout-body"><p><code>&gt;</code> → request (what you sent) and <code>&lt;</code> → response (what you got back)</p>
</div>
    </aside>

<p>This is the view the browser hides. When &quot;Something went wrong&quot;, the status line and headers here usually tell you what.</p>
<h2 id="get-reads-post-sends">GET Reads, POST Sends<a class="heading-anchor" href="#get-reads-post-sends" aria-label="Link to this section">#</a></h2>
<h4 id="get-i-want-to-read-something">GET - &quot;I want to read something&quot;<a class="heading-anchor" href="#get-i-want-to-read-something" aria-label="Link to this section">#</a></h4>
<p>GET is like asking a question or looking something up. You request information without changing anything:</p>
<ul>
<li>Opening a website in your browser</li>
<li>Searching Google</li>
<li>Checking the weather</li>
<li>Looking at your bank balance</li>
</ul>
<div class="code-block">
      <div class="code-head">
        <span class="code-lang"></span>
        <button type="button" class="code-copy">Copy</button>
      </div>
      <pre class="shiki"><code>curl https://api.github.com/users/octocat</code></pre>
    </div><p>This asks: &quot;Hey GitHub, can I see octocat&#39;s profile?&quot; GET is curl&#39;s default, so you don&#39;t need <code>-X GET</code>.</p>
<h4 id="post-i-want-to-send-or-create-something">POST - &quot;I want to send or create something&quot;<a class="heading-anchor" href="#post-i-want-to-send-or-create-something" aria-label="Link to this section">#</a></h4>
<p>POST is like filling out a form and submitting it. You send data to create or update something:</p>
<ul>
<li>Submitting a contact form</li>
<li>Creating a new social media post</li>
<li>Logging into a website</li>
<li>Uploading a file</li>
</ul>
<div class="code-block">
      <div class="code-head">
        <span class="code-lang"></span>
        <button type="button" class="code-copy">Copy</button>
      </div>
      <pre class="shiki"><code>curl -X POST https://httpbin.org/post \
  -d &quot;username=john&amp;password=secret123&quot;</code></pre>
    </div><p>This says: &quot;Hey server, here&#39;s some data I want to send you.&quot;</p>
<hr>
<p>So the next time an API call fails with nothing but &quot;Something went wrong&quot;, copy the request into <code>curl -v</code> and read what the server actually said.</p>
