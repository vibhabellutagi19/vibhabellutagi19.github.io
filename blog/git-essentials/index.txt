13:T1974,<p>If you have ever played a video game, you know the anxiety of facing a difficult boss. What is the first thing you do before walking through that boss door? You save your game.</p>
<p>Why? Because if you rush in and lose all your health, you don&#39;t want to restart the entire game from level one. You want to respawn right where you were, with all your items and progress intact.</p>
<p><code>Git</code> is exactly that—but for coding.</p>
<p>It allows you to create Save Points in your project. If you write a bunch of code and accidentally break your entire app, you don&#39;t have to panic. You just &quot;reload&quot; your last save, and you are back in business.</p>
<p>In this blog, we will go through the basics of Git, so that you can code without the fear of losing your progress.</p>
<h2>Introduction to Git</h2>
<h3>What is Git?</h3>
<p>Git is a distributed version control system - which means that code on a local machine is a complete version control repository. It helps developers to commit their local changes, test them and sync it with a remote repository when they are ready.</p>
<h3>Why Use Git?</h3>
<p>The major difference between Git and any other version control system is the way git thinks about data. Most version control systems stores information as a list of file-based changes. But git stores as a set of files and the changes made to each file.</p>
<p>This approach has several advantages:</p>
<ol>
<li><strong>Distributed Development</strong>: Every developer has a full copy of the repository, including its history. This allows for offline work and faster access to project history.</li>
<li><strong>Branching and Merging</strong>: Git makes it easy to create branches for new features or bug fixes. Merging these branches back into the main codebase is efficient and straightforward.</li>
<li><strong>Pull Requests and Code Reviews</strong>: Platforms like GitHub and GitLab leverage Git&#39;s capabilities to facilitate collaboration through pull requests and code reviews.</li>
<li><strong>Data Integrity</strong>: Git uses SHA-1 hashing to ensure the integrity of the data. Every file and commit is checksummed, and any corruption can be detected.</li>
<li><strong>Speed</strong>: Git is designed to be fast. Most operations are performed locally, which makes tasks like committing, branching, and merging very quick.</li>
</ol>
<h3>Core terms in Git</h3>
<ol>
<li><strong>Repository (Repo)</strong>: A directory that contains your project files and the entire history of changes made to those files. This directory is pushed to a remote server like GitHub or GitLab.</li>
<li><strong>Branch</strong>: A separate line of development in your repository. You can create branches to work on new features or bug fixes without affecting the main codebase.</li>
<li><strong>Commit</strong>: &quot;Save Point&quot; - Every change you make to the files in your repository is saved as a commit. Each commit has a unique ID and a message describing the changes.</li>
<li><strong>Stage</strong>: Selecting specifically which changes you want to include in your next commit.</li>
<li><strong>Head</strong>: &quot;tu es ici&quot; - A marker indicating which Save Point (Commit) you are currently playing.</li>
</ol>
<p>Its important also to understand about the <code>The Three States</code> in Git:</p>
<ol>
<li><strong>Modified</strong>: The changes have been made to the file but not yet committed in the database.</li>
<li><strong>Staged</strong>: The changes have been staged for the next commit, only the staged changes will be included in the next commit.</li>
<li><strong>Committed</strong>: The changes have been committed to the repository.</li>
</ol>
<p><img src="/posts/2026-01-13-git-essentials/assets/three-states.png" alt="The Three States in Git" loading="lazy" /></p>
<h3>Basic Git Commands</h3>
<p>Let&#39;s go through some essential Git commands in perspective of a game:</p>
<ol>
<li>Start a New game with <code>git init</code>: This command initializes a new Git repository in your project directory. It&#39;s like starting a new game.</li>
</ol>
<pre><code>mkdir git-game
cd git-game
git init
</code></pre>
<ol start="2">
<li>Check your current position with <code>git status</code>: This command shows the current state of your repository, including any changes that have been made but not yet committed. It&#39;s like checking your inventory and health status.</li>
</ol>
<pre><code>git status
</code></pre>
<ol start="3">
<li><p>Create Content - Create a file named story.txt and type &quot;Chapter 1: The Hero Wakes Up.&quot; If you run <code>git status</code> now, the text will be Red. This means Git sees a new file, but it isn&#39;t prepared to be saved yet.</p>
</li>
<li><p>Prepare the Save - <code>git add</code>¯<br>In a game, you might organize your inventory before saving. In Git, this is called Staging. We have to tell Git which files we want to put in the save capsule.</p>
</li>
</ol>
<pre><code>git add story.txt
</code></pre>
<aside class="callout callout-tip">
      <p class="callout-title">Tip</p>
      <div class="callout-body"><p>Type git add . to add EVERYTHING that changed at once.</p>
</div>
    </aside>

<p>Run <code>git status</code> again. The file will turn Green. It is now &quot;Staged&quot; and ready to be committed.</p>
<ol start="5">
<li>Create the Save Point - <code>git commit</code><br>This is the moment you actually press the &quot;Save&quot; button. You must leave a message so you remember why you saved here.</li>
</ol>
<pre><code>git commit -m &quot;Started the story with Chapter 1&quot;
</code></pre>
<p>Success! You have created a permanent checkpoint. You can now delete story.txt, change it, or break it, and you will always be able to return to this exact state.</p>
<ol start="6">
<li>View Your Saves (<code>git log</code>)<br>Want to see your list of save points?</li>
</ol>
<pre><code>git log
</code></pre>
<p>This prints a journal of every save, who made it, when they made it, and the message they left.</p>

<h2>Conclusion</h2>
<p><img src="/posts/2026-01-13-git-essentials/assets/overall.png" alt="Git Save Point" loading="lazy" /></p>
<p>So isnt it cool how Git lets you create Save Points in your coding journey? Which has made it so much easier to manage changes, collaborate with others, and keep your code safe. The best part is, Git allows you to make mistakes. And in programming, making mistakes is the only way to learn. So go ahead—break things, fix them, and commit often!</p>
