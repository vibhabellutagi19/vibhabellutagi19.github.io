<p>This post covers how JavaScript picks <code>this</code>, then the three methods that let you set it, and how each one would fix the bug above.</p>
<h2 id="this-is-decided-at-call-time"><code>this</code> Is Decided at Call Time<a class="heading-anchor" href="#this-is-decided-at-call-time" aria-label="Link to this section">#</a></h2>
<p><code>this</code> refers to the context a function runs in. The rule that explains almost everything about it: <strong><code>this</code> depends on how a function is called, not where it&#39;s defined.</strong></p>
<ul>
<li>Called as a method of an object (<code>user.greet()</code>), <code>this</code> is that object.</li>
<li>Called as a standalone function (<code>greet()</code>), <code>this</code> is the global object in non-strict mode, or <code>undefined</code> in strict mode.</li>
</ul>
<p>In the example above, <code>setTimeout</code> receives only the function, not the object it came from. When it calls the function later, it&#39;s a plain call, so <code>this</code> is no longer <code>user</code>.</p>

<h2 id="call-apply-and-bind-let-you-choose-this"><code>call</code>, <code>apply</code> and <code>bind</code> Let You Choose <code>this</code><a class="heading-anchor" href="#call-apply-and-bind-let-you-choose-this" aria-label="Link to this section">#</a></h2>

<span class="line"><span style="color:#66707B">// → "Hey, Alice?"</span></span></code></pre>
    </div><p><strong>Syntax:</strong> <code>fn.apply(thisArg, [arg1, arg2, ...])</code></p>
<p>🧠 <strong>Mental model:</strong> Same as <code>call</code>, but you <strong>apply</strong> a whole list of arguments at once, like handing someone a <em>sheet of paper</em> with everything on it instead of saying each thing one by one.</p>
<hr>
<h4 id="3-bind-borrow-get-back-a-new-function-doesnt-run-yet">3. <code>bind</code> — borrow &amp; get back a <em>new</em> function (doesn&#39;t run yet)<a class="heading-anchor" href="#3-bind-borrow-get-back-a-new-function-doesnt-run-yet" aria-label="Link to this section">#</a></h4>
<div class="code-block">
      <div class="code-head">
        <span class="code-lang">JavaScript</span>
        <button type="button" class="code-copy">Copy</button>
      </div>
      <pre class="shiki github-light-high-contrast" tabindex="0"><code><span class="line"><span style="color:#A0111F">const</span><span style="color:#023B95"> greetAlice</span><span style="color:#A0111F"> =</span><span style="color:#0E1116"> greet.</span><span style="color:#622CBC">bind</span><span style="color:#0E1116">(person, </span><span style="color:#032563">"Hi"</span><span style="color:#0E1116">);</span></span>
<span class="line"></span>
<span class="line"><span style="color:#66707B">// ... later ...</span></span>
<span class="line"><span style="color:#622CBC">greetAlice</span><span style="color:#0E1116">(</span><span style="color:#032563">"!!"</span><span style="color:#0E1116">);</span></span>
<span class="line"><span style="color:#66707B">// → "Hi, Alice!!"</span></span></code></pre>
    </div><p><strong>Syntax:</strong> <code>const newFn = fn.bind(thisArg, arg1, ...)</code></p>
<p><code>bind</code> also lets you <strong>pre-fill</strong> some arguments (called <em>partial application</em>).</p>
<p>🧠 <strong>Mental model:</strong> Think of <code>bind</code> as a <strong>sticky note</strong>: you write down who <code>this</code> is, pre-fill some args, and stick it on the function. The function doesn&#39;t run until <em>you</em> decide to call it later.</p>

<h3 id="the-one-line-summary-for-each">The one-line summary for each<a class="heading-anchor" href="#the-one-line-summary-for-each" aria-label="Link to this section">#</a></h3>
<ul>
<li><code>call</code> → <em>&quot;Run this function NOW, with this</em> <code>this</code><em>, passing args separately&quot;</em></li>
<li><code>apply</code> → <em>&quot;Run this function NOW, with this</em> <code>this</code><em>, passing args as an array&quot;</em></li>
<li><code>bind</code> → <em>&quot;Give me a new function with</em> <code>this</code> <em>(and maybe some args) locked in — I&#39;ll call it later&quot;</em></li>
</ul>
<h2 id="back-to-the-settimeout-bug">Back to the setTimeout Bug<a class="heading-anchor" href="#back-to-the-settimeout-bug" aria-label="Link to this section">#</a></h2>
<p><code>setTimeout</code> calls the function later, so <code>call</code> and <code>apply</code> don&#39;t fit: they run it immediately. <code>bind</code> is the one that fits, because it returns a function with <code>this</code> locked in:</p>
<div class="code-block">
      <div class="code-head">
        <span class="code-lang">JavaScript</span>
        <button type="button" class="code-copy">Copy</button>
      </div>
      <pre class="shiki github-light-high-contrast" tabindex="0"><code><span class="line"><span style="color:#622CBC">setTimeout</span><span style="color:#0E1116">(user.greet.</span><span style="color:#622CBC">bind</span><span style="color:#0E1116">(user), </span><span style="color:#023B95">0</span><span style="color:#0E1116">);  </span><span style="color:#66707B">// Hi, alice</span></span></code></pre>
    </div><p>Whenever you hand a method to something else to call later (a timer, an event listener, a callback), the object doesn&#39;t come with it. <code>bind</code> is how you send it along.</p>
