    </div><p>Same language. Same idea of a global object. A different name.</p>
<blockquote>
<p><code>globalThis</code> is the one name for the global object that works in every JavaScript environment.</p>
</blockquote>
<p>This post covers what the global object is, why it ended up with a different name in each environment, how <code>globalThis</code> fixes that, and why you should still use it sparingly.</p>
<aside class="callout callout-tldr">
      <p class="callout-title">TL;DR</p>
      <div class="callout-body"><p><strong>Problem:</strong> the global object is called <code>window</code> in browsers, <code>global</code> in Node.js and <code>self</code> in Web Workers, so code that touches it breaks when it runs somewhere else.</p>
<p><strong>Fix:</strong> use <code>globalThis</code> (ES2020), which works everywhere. But prefer module exports over globals: reach for <code>globalThis</code> only when something truly must be global.</p>
</div>

<h2 id="global-variables-live-on-an-object">Global Variables Live on an Object<a class="heading-anchor" href="#global-variables-live-on-an-object" aria-label="Link to this section">#</a></h2>
<p>Scope answers one question:</p>
<blockquote>
<p>Where in your code can this variable be seen and used?</p>
</blockquote>
<p>A variable declared inside a function or a <code>{ }</code> block is only visible there. A variable at the top level is visible everywhere:</p>
<div class="code-block">

    </div><p>But what does &quot;everywhere&quot; actually mean? JavaScript always has a container that holds the things available everywhere: built-ins like <code>setTimeout</code>, <code>fetch</code> and <code>console</code>, plus anything you attach to it yourself. That container is the <strong>global object</strong>.</p>
<p>Every JavaScript environment has one, but each environment named it differently:</p>

<h2 id="three-names-for-one-object">Three Names for One Object<a class="heading-anchor" href="#three-names-for-one-object" aria-label="Link to this section">#</a></h2>
<p>The global object means the same thing in every environment, but it goes by a different name in each one. To write code that worked everywhere, such as a library used in both the browser and Node.js, developers had to detect which environment they were in:</p>
<div class="code-block">
      <div class="code-head">
        <span class="code-lang">JavaScript</span>
        <button type="button" class="code-copy">Copy</button>
      </div>
      <pre class="shiki github-light-high-contrast" tabindex="0"><code><span class="line"><span style="color:#A0111F">function</span><span style="color:#622CBC"> getGlobalObject</span><span style="color:#0E1116">() {</span></span>
<span class="line"><span style="color:#A0111F">  if</span><span style="color:#0E1116"> (</span><span style="color:#A0111F">typeof</span><span style="color:#0E1116"> window </span><span style="color:#A0111F">!==</span><span style="color:#032563"> 'undefined'</span><span style="color:#0E1116">) </span><span style="color:#A0111F">return</span><span style="color:#0E1116"> window;   </span><span style="color:#66707B">// Browser</span></span>
<span class="line"><span style="color:#A0111F">  if</span><span style="color:#0E1116"> (</span><span style="color:#A0111F">typeof</span><span style="color:#0E1116"> global </span><span style="color:#A0111F">!==</span><span style="color:#032563"> 'undefined'</span><span style="color:#0E1116">) </span><span style="color:#A0111F">return</span><span style="color:#0E1116"> global;   </span><span style="color:#66707B">// Node.js</span></span>
<span class="line"><span style="color:#A0111F">  if</span><span style="color:#0E1116"> (</span><span style="color:#A0111F">typeof</span><span style="color:#0E1116"> self </span><span style="color:#A0111F">!==</span><span style="color:#032563"> 'undefined'</span><span style="color:#0E1116">) </span><span style="color:#A0111F">return</span><span style="color:#0E1116"> self;       </span><span style="color:#66707B">// Web Workers</span></span>
<span class="line"><span style="color:#A0111F">  throw</span><span style="color:#A0111F"> new</span><span style="color:#622CBC"> Error</span><span style="color:#0E1116">(</span><span style="color:#032563">'Unable to locate global object'</span><span style="color:#0E1116">);  </span><span style="color:#66707B">// Unknown environment</span></span>
<span class="line"><span style="color:#0E1116">}</span></span>
<span class="line"></span>
<span class="line"><span style="color:#A0111F">const</span><span style="color:#023B95"> globalObj</span><span style="color:#A0111F"> =</span><span style="color:#622CBC"> getGlobalObject</span><span style="color:#0E1116">();</span></span></code></pre>
    </div><p>This approach was error-prone. Some versions added a last-resort fallback of <code>this</code>, which only works in non-strict scripts: in strict mode and in ES modules, top-level <code>this</code> is <code>undefined</code>, so the fallback silently breaks. It was too much boilerplate just to do one simple thing, access the global object.</p>
<h2 id="globalthis-is-the-name-that-works-everywhere">globalThis Is the Name That Works Everywhere<a class="heading-anchor" href="#globalthis-is-the-name-that-works-everywhere" aria-label="Link to this section">#</a></h2>
<p><code>globalThis</code>, introduced in ES2020, makes that function unnecessary. It&#39;s a single, standard name for the global object, with no environment checks and no fragile fallbacks.</p>
<div class="code-block">
      <div class="code-head">
        <span class="code-lang">JavaScript</span>
        <button type="button" class="code-copy">Copy</button>
      </div>
      <pre class="shiki github-light-high-contrast" tabindex="0"><code><span class="line"><span style="color:#66707B">// ❌ Before — environment detection</span></span>
<span class="line"><span style="color:#A0111F">const</span><span style="color:#023B95"> globalObj</span><span style="color:#A0111F"> =</span><span style="color:#622CBC"> getGlobalObject</span><span style="color:#0E1116">();</span></span>
<span class="line"><span style="color:#0E1116">globalObj.myVar </span><span style="color:#A0111F">=</span><span style="color:#023B95"> 42</span><span style="color:#0E1116">;</span></span>
<span class="line"></span>
<span class="line"><span style="color:#66707B">// ✅ After — works in browsers, Node.js and Web Workers</span></span>
<span class="line"><span style="color:#0E1116">globalThis.myVar </span><span style="color:#A0111F">=</span><span style="color:#023B95"> 42</span><span style="color:#0E1116">;</span></span>
<span class="line"><span style="color:#0E1116">console.</span><span style="color:#622CBC">log</span><span style="color:#0E1116">(globalThis.myVar); </span><span style="color:#66707B">// 42</span></span></code></pre>
    </div><p><strong>Benefits of</strong> <code>globalThis</code><strong>:</strong></p>
<ol>
<li><strong>Available everywhere</strong> - built into every modern JavaScript environment. No imports, no setup.</li>
<li><strong>Simpler code</strong> - one consistent reference instead of a detection function.</li>
<li><strong>Readable</strong> - any developer immediately knows what <code>globalThis</code> refers to.</li>
</ol>
<p>A common use is checking whether a feature exists, without caring where the code runs:</p>
<div class="code-block">
      <div class="code-head">
        <span class="code-lang">JavaScript</span>
        <button type="button" class="code-copy">Copy</button>

<span class="line"><span style="color:#0E1116">  console.</span><span style="color:#622CBC">log</span><span style="color:#0E1116">(</span><span style="color:#032563">'fetch is supported'</span><span style="color:#0E1116">);</span></span>
<span class="line"><span style="color:#0E1116">} </span><span style="color:#A0111F">else</span><span style="color:#0E1116"> {</span></span>
<span class="line"><span style="color:#0E1116">  console.</span><span style="color:#622CBC">log</span><span style="color:#0E1116">(</span><span style="color:#032563">'fetch is not supported'</span><span style="color:#0E1116">);</span></span>
<span class="line"><span style="color:#0E1116">}</span></span></code></pre>
    </div><h2 id="use-it-rarely-because-globals-are-shared-by-everyone">Use It Rarely, Because Globals Are Shared by Everyone<a class="heading-anchor" href="#use-it-rarely-because-globals-are-shared-by-everyone" aria-label="Link to this section">#</a></h2>
<p><code>globalThis</code> makes the global object easy to reach. That doesn&#39;t make globals a good idea.</p>
<blockquote>
<p>Use <code>globalThis</code> only when something genuinely needs to be reachable from your entire program, across different environments.</p>
</blockquote>
<p><strong>Good use cases:</strong></p>
<ul>
<li>Writing a library or utility that runs in both the browser and Node.js</li>
<li>Feature detection across environments</li>
<li>Polyfilling missing features</li>
</ul>
<p><strong>Avoid it when:</strong></p>
<ul>
<li>A regular variable or module export would do the job</li>
<li>You&#39;re tempted to use it just to avoid passing data around properly</li>
</ul>
<h3 id="dont-pollute-the-global-scope">⚠️ Don&#39;t Pollute the Global Scope<a class="heading-anchor" href="#dont-pollute-the-global-scope" aria-label="Link to this section">#</a></h3>
<p>Every property you add to <code>globalThis</code> is visible to every file in your program, including third-party code:</p>
<div class="code-block">
      <div class="code-head">
        <span class="code-lang">JavaScript</span>
        <button type="button" class="code-copy">Copy</button>
      </div>
      <pre class="shiki github-light-high-contrast" tabindex="0"><code><span class="line"><span style="color:#66707B">// ❌ Bad — polluting the global scope</span></span>
<span class="line"><span style="color:#0E1116">globalThis.username </span><span style="color:#A0111F">=</span><span style="color:#032563"> 'Alice'</span><span style="color:#0E1116">;</span></span>
<span class="line"><span style="color:#0E1116">globalThis.</span><span style="color:#622CBC">fetchData</span><span style="color:#A0111F"> =</span><span style="color:#A0111F"> function</span><span style="color:#0E1116">() { </span><span style="color:#A0111F">...</span><span style="color:#0E1116"> };</span></span>
<span class="line"><span style="color:#0E1116">globalThis.config </span><span style="color:#A0111F">=</span><span style="color:#0E1116"> { debug: </span><span style="color:#023B95">true</span><span style="color:#0E1116"> };</span></span>
<span class="line"></span>
<span class="line"><span style="color:#66707B">// ✅ Good — keep things scoped with modules</span></span>
<span class="line"><span style="color:#A0111F">export</span><span style="color:#A0111F"> const</span><span style="color:#023B95"> username</span><span style="color:#A0111F"> =</span><span style="color:#032563"> 'Alice'</span><span style="color:#0E1116">;</span></span>
<span class="line"><span style="color:#A0111F">export</span><span style="color:#A0111F"> function</span><span style="color:#622CBC"> fetchData</span><span style="color:#0E1116">() { </span><span style="color:#A0111F">...</span><span style="color:#0E1116"> }</span></span>
<span class="line"><span style="color:#A0111F">export</span><span style="color:#A0111F"> const</span><span style="color:#023B95"> config</span><span style="color:#A0111F"> =</span><span style="color:#0E1116"> { debug: </span><span style="color:#023B95">true</span><span style="color:#0E1116"> };</span></span></code></pre>
    </div><p>Polluting globals leads to:</p>
<ul>
<li><strong>Name collisions</strong>: two files accidentally overwrite each other&#39;s variables</li>
<li><strong>Harder debugging</strong>: values change from places you didn&#39;t expect</li>
<li><strong>Unpredictable code</strong>: any file can depend on anything</li>
</ul>
<h2 id="global-vs-globalthis">global vs globalThis<a class="heading-anchor" href="#global-vs-globalthis" aria-label="Link to this section">#</a></h2>
